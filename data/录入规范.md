# 历史星图 · 数据录入规范

## 一、工作流概述

由于 Render Free 版**没有持久化磁盘**和**没有 Shell 访问**，数据必须通过以下方式持久化：

```
1. 编辑 JSON 数据文件 → 2. 本地运行导入脚本 → 3. git commit 提交数据库 → 4. 自动重新部署
```

每次添加数据后，都需要重新部署。这是 Free 版的唯一可行方案。

## 二、目录结构

```
server/data/
├── 录入规范.md          # 本文档
├── seed-data.js         # 数据导入脚本（不要修改）
├── 春秋战国/
│   ├── 史记-人物.json
│   └── 史记-事件.json
├── 秦汉/
│   ├── 史记-人物.json
│   ├── 史记-事件.json
│   └── 汉书-人物.json
├── 三国/
│   ├── 三国志-人物.json
│   └── 三国演义-事件.json
└── ...
```

**按朝代/史书分类**，方便管理和溯源。


### 字段说明

| 字段 | 必填 | 类型 | 说明 |
|------|------|------|------|
| `id` | ✅ | string | 唯一标识，小写拼音，如 `liubei` |
| `type` | ✅ | string | 固定为 `"person"` |
| `name` | ✅ | string | 中文名 |
| `alias` | ❌ | string | 字号/谥号，如 `"字玄德"` |
| `born` | ❌ | number | 出生年份（公元纪年） |
| `died` | ❌ | number | 逝世年份 |
| `dynasty` | ❌ | string | 所属朝代 `id`（需先在 dynasties 中定义） |
| `role` | ❌ | string[] | 角色标签，如 `["政治家","军事家"]` |
| `short` | ❌ | string | 短简介（50字以内） |
| `intro` | ❌ | string | 完整生平（无限制） |
| `achievements` | ❌ | string[] | 主要成就列表 |
| `controversy` | ❌ | string | 争议与评价 |
| `quote` | ❌ | string | 名言/代表作引用 |
| `quoteSrc` | ❌ | string | 名言出处 |
| `works` | ❌ | string[] | 著作列表 |
| `sources` | ❌ | object[] | 史料来源（见下） |
| `life` | ❌ | object[] | 生平事件（见下） |
| `relations` | ❌ | object[] | 人物关系（见下） |
| `events` | ❌ | string[] | 参与的事件 `id` 列表 |
| `locations` | ❌ | string[] | 关联地点 `id` 列表 |

#### `sources` 格式

```json
{ "t": "史料名称", "lv": "A" }
```

- `t`：史料名称，建议加书名号
- `lv`：可信度等级
  - `A` = 原始史料（正史原文、文集）
  - `B` = 权威整理（学者专著、点校本）
  - `C` = 通俗资料（传记、网文）
  - `D` = 待校验

#### `life` 格式（生平事件线）

```json
{ "y": 年份, "key": true/false, "t": "事件标题", "s": "简要说明" }
```

- `y`：年份（公元前用负数，如 `-202`）
- `key`：`true` 表示重要事件，在时间线上显示为节点
- `t`：事件标题（10字以内）
- `s`：简要说明（20字以内）

#### `relations` 格式（人物关系）

```json
{ "to": "目标人物id", "type": "关系类型", "label": "关系标签", "desc": "关系说明" }
```

**关系类型**（全部大写）：

| 类型 | 含义 | 示例 |
|------|------|------|
| `TEACHER_OF` | 教导/举荐 | 曾国藩→李鸿章 |
| `STUDENT_OF` | 被教导/受举荐 | 李鸿章→曾国藩 |
| `COLLEAGUE_OF` | 同僚/合作 | 曾国藩→左宗棠 |
| `RIVAL_OF` | 敌对/政争 | 曾国藩→洪秀全 |
| `SERVE_AS` | 君臣/事主 | 李鸿章→慈禧 |
| `SPOUSE_OF` | 亲属/婚姻 | 慈禧→咸丰帝 |
| `PARTICIPATED_IN` | 参与事件 | 李鸿章→太平天国 |
| `LED` | 领导/创立 | 洪秀全→太平天国 |

## 四、事件数据格式

```json
{
  "events": {
    "battleredcliffs": {
      "id": "battleredcliffs",
      "type": "event",
      "name": "赤壁之战",
      "dynasty": "han",
      "start": 208,
      "end": 208,
      "place": "赤壁（今湖北赤壁）",
      "placeId": "chibi",
      "short": "奠定三国鼎立格局的决定性战役...",
      "bg": "背景描述...",
      "process": "过程描述...",
      "result": "结果与影响...",
      "controversy": "争议...",
      "chain": [
        { "id": "self", "name": "赤壁之战", "y": 208, "note": "本事件", "cur": true },
        { "id": "nanjun", "name": "南郡之战", "y": 209, "note": "后续·周瑜攻曹仁" }
      ],
      "persons": ["liubei", "guanyu", "zhugeliang", "zhouyu", "caocao"],
      "related": ["threekingdoms"],
      "sources": [
        { "t": "《三国志》", "lv": "A" },
        { "t": "《资治通鉴》", "lv": "A" }
      ]
    }
  }
}
```

### 字段说明

| 字段 | 必填 | 类型 | 说明 |
|------|------|------|------|
| `id` | ✅ | string | 唯一标识，如 `battleredcliffs` |
| `type` | ✅ | string | 固定为 `"event"` |
| `name` | ✅ | string | 事件名称 |
| `dynasty` | ❌ | string | 所属朝代 `id` |
| `start` / `end` | ❌ | number | 起止年份 |
| `place` | ❌ | string | 地点描述 |
| `placeId` | ❌ | string | 地点 `id`（需先在 locations 中定义） |
| `short` | ❌ | string | 短简介 |
| `bg` | ❌ | string | 背景 |
| `process` | ❌ | string | 过程 |
| `result` | ❌ | string | 结果与影响 |
| `controversy` | ❌ | string | 争议 |
| `chain` | ❌ | object[] | 事件链（见下） |
| `persons` | ❌ | string[] | 参与人物 `id` 列表 |
| `related` | ❌ | string[] | 关联事件 `id` 列表 |
| `sources` | ❌ | object[] | 史料来源（同人物） |

#### `chain` 格式（事件链）

```json
[
  { "id": "前事件id", "name": "前事件名", "y": 年份, "note": "前因·说明" },
  { "id": "self", "name": "本事件名", "y": 年份, "note": "本事件", "cur": true },
  { "id": "后事件id", "name": "后事件名", "y": 年份, "note": "后果·说明" }
]
```

- 当前事件用 `"id": "self"` 和 `"cur": true` 标记
- 事件间用 `"to": "事件id"` 连接（可选）

## 六、录入步骤

### 1. 创建数据文件

在 `server/data/朝代/史书-类型.json` 路径下创建 JSON 文件。例如：

```bash
server/data/秦汉/史记-人物.json
```

### 2. 填写数据

按上述格式填写人物/事件/地点数据。每次添加一个完整的人物或事件，确保：
- `id` 全局唯一（不与其他文件冲突）
- 引用的 `dynasty` `id` 已在 `dynasties` 表中存在
- 引用的 `placeId` 已在 `locations` 中定义
- 引用的 `events` 中的人物 `id` 已存在或即将在同一批创建

### 3. 运行导入脚本

```bash
cd server
node scripts/seed-data.js
```

此脚本会：
- 扫描 `data/` 目录下所有 `.json` 文件
- 合并所有数据
- 清空数据库现有数据
- 重新导入全部数据

### 4. 验证数据

```bash
sqlite3 history-atlas.db "SELECT COUNT(*) FROM persons;"
sqlite3 history-atlas.db "SELECT COUNT(*) FROM events;"
```

### 5. 提交并推送

```bash
git add data/ history-atlas.db
git commit -m "data: 添加《史记》XX人物/XX事件"
git push origin main
```

Render 会自动检测到新提交，重新构建部署。

## 七、注意事项

1. **id 唯一性**：所有 `id` 在整个数据库中必须唯一。建议使用 `拼音名` 或 `朝代_拼音` 格式，如 `qin_shihuang`。

2. **朝代引用**：`dynasty` 字段的值必须是以下之一：
   ```
   xia, shang, zhou, qin, han, sanguo, jin, nanbei, sui, tang, song, yuan, ming, qing
   ```

3. **年份表示**：
   - 公元前用负数：`"born": -259`（秦始皇生于前259年）
   - 公元后为正数：`"born": 161`（刘备生于161年）
   - 跨世纪年份：`"start": 184, "end": 220`（东汉末年到曹魏建立）

4. **来源等级**：务必标注史料等级，保证数据质量。优先使用 `A` 级原始史料。

5. **JSON 语法**：确保 JSON 格式正确，可用 [jsonlint.com](https://jsonlint.com) 验证。

6. **避免重复**：如果同一人物在不同史书中都有记载，只录入一次，在 `sources` 中列出所有来源。

7. **关系互指**：如果 A 与 B 有关系，建议只在一方定义，避免重复。

## 九、批量导入工具

提供了 `scripts/seed-data.js` 脚本，自动完成：
- 扫描 `data/` 目录所有 JSON 文件
- 合并并去重
- 按依赖顺序导入（先 dynasty/location → 再 person/event → 再 relation/source）
- 清空旧数据后重新导入

```bash
cd server
node scripts/seed-data.js
```
